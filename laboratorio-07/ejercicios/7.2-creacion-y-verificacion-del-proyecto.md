# Creación del proyecto y verificación de la configuración (7.2)

## 1. Creación con Spring Initializr (start.spring.io)
| Campo | Valor |
|---|---|
| Project | Maven |
| Language | Java |
| Spring Boot | 4.1.2 (el que quedó en mi `pom.xml`; el laboratorio indica 4.1.1, compatible) |
| Group | `com.example` |
| Artifact / Name | `petmatch-lab` |
| Package name | `com.example.petmatch_lab` (el que genera Initializr) |
| Packaging | Jar |
| Java | 21 |
| Dependencias | Spring Web MVC, Thymeleaf |

La clase principal es `PetmatchLabApplication`, en el paquete raíz `com.example.petmatch_lab`; los controladores, el servicio y el repositorio están en subpaquetes suyos, por eso Spring los encuentra.

## 2. Verificación del JDK
```
java --version     -> _(pegar salida; debe indicar 21)_
javac --version    -> _(pegar salida; debe indicar 21)_
```

## 3. Verificación de `pom.xml`
| Elemento | Valor en el proyecto | Comprobado |
|---|---|---|
| `<parent>` | `spring-boot-starter-parent` 4.1.2 (administra versiones) | sí |
| `groupId` / `artifactId` | `com.example` / `petmatch-lab` | sí |
| `<java.version>` | 21 | sí |
| Starter web | `spring-boot-starter-webmvc` | sí |
| Starter plantillas | `spring-boot-starter-thymeleaf` | sí |
| Starters de prueba (`test`) | `spring-boot-starter-webmvc-test` y `spring-boot-starter-thymeleaf-test` | sí |
| Plugin | `spring-boot-maven-plugin` | sí |

Diferencias con el ejemplo del laboratorio, todas compatibles: versión del parent 4.1.2 en lugar de 4.1.1, un starter de pruebas adicional (`thymeleaf-test`, lo agrega Initializr al elegir Thymeleaf) y `<name>` completado con `petmatch-lab` (venía vacío). Ningún starter lleva número de versión: la administra el parent.

## 4. Configuración
`src/main/resources/application.yaml`:
```yaml
spring:
  application:
    name: petmatch-lab

server:
  port: 8080
```
Se eliminó `application.properties` para no duplicar `spring.application.name`.

## 5. Ejecución con Maven Wrapper
Desde la carpeta que contiene `pom.xml`:
```
./mvnw compile                 # Windows: .\mvnw.cmd compile
./mvnw test
./mvnw spring-boot:run
```
Salida observada:
- `compile`: _(pegar resultado: BUILD SUCCESS)_
- `test`: _(pegar resultado: Tests run: ..., Failures: 0)_
- `spring-boot:run`: _(pegar la línea de la consola que indica que Tomcat/servidor escucha en el puerto 8080)_

Con la aplicación en marcha, `http://localhost:8080/` muestra la página de inicio y `http://localhost:8080/unknown` responde 404.
