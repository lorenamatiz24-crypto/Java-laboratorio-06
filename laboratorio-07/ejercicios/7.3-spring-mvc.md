# Práctica 7.3 — Spring MVC: rutas, controladores y vistas

## Antes de ejecutar
- `/` → enlace "Explorar mascotas" abre `/pets` (`PetController.list`); "Inicio" y la marca abren `/` (`HomeController.home`).
- `/about` lo atiende `HomeController.about`.
- `/unknown`: sin método asociado → 404.

## Ejercicio — segundo atributo `projectName`
```java
model.addAttribute("projectName", "PetMatch Mini");
```
```html
<p>Proyecto: <strong th:text="${projectName}">Nombre del proyecto</strong></p>
```
La clave del `Model` y la expresión `${projectName}` deben coincidir exactamente (incluidas mayúsculas).

## Depuración
1. `return "homes"`: la ruta existe pero no `homes.html` → error 500 (*Error resolving template [homes]*).
2. `${welcomeMessage}` sin atributo: con `th:text` se evalúa como nulo, el párrafo queda vacío y la respuesta sigue siendo 200 (distinto de ruta inexistente → 404, plantilla inexistente → 500).
3. `@GetMapping("/welcome")`: queda registrada `/welcome`; `/` da 404.

## Comprobación
- `@Controller` marca la clase como controlador; `@GetMapping` asocia una ruta GET con un método.
- Se devuelve una cadena porque es el nombre lógico de la vista (`templates/home.html`), no texto a imprimir.
- `Model` es el contenedor de atributos para la vista.
- `${message}` se procesa en el servidor al generar la respuesta.
